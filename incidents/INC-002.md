# INC-002 — Repeated Sudo Privilege Activity

**Title:** Repeated Sudo Privilege Activity  
**Severity:** Medium  
**Status:** Closed  
**Source:** Ubuntu Server local user activity  
**Destination:** `ubuntu-server`  
**Detection:** Sudo activity threshold search

## Summary
Controlled sudo activity was generated on the Ubuntu Splunk VM. Splunk ingested the corresponding authentication events and the detection search identified 15 sudo-related events during the selected five-minute window.

## Technical Evidence
- Host: `ubuntu-server`
- Source: `/var/log/auth.log`
- Sourcetype: `linux_secure`
- Detection result: `ubuntu-server` — `15` events
- Observed command activity included repeated `sudo ... COMMAND=/usr/bin/whoami` records.

## Timeline
- Controlled sudo commands executed on Ubuntu.
- Authentication events written to `/var/log/auth.log`.
- Splunk indexed the events under `soc_lab`.
- Five-minute detection search returned 15 events.

## Indicators
- Host: `ubuntu-server`
- Event keyword: `sudo:`
- Repeated privileged command execution

## Analysis
The events demonstrate repeated privilege-use activity. The lab evidence does not by itself establish malicious privilege escalation; the activity was intentionally generated for detection testing.

## Impact
No production impact. Activity occurred in the controlled lab.

## Containment Recommendation
In production, correlate repeated sudo use with the user, command, change ticket, and surrounding authentication activity. Investigate activity that is not authorized or expected.

## Lessons Learned
- Sudo events are available through Linux authentication logging.
- Simple keyword-based searches can provide useful SOC triage signals.
- Context is required before classifying privileged activity as malicious.
